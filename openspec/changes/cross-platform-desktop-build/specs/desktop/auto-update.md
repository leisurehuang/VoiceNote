## Purpose

使桌面应用能够在不重新安装的情况下自动更新到新版本，提升用户体验和减少维护负担。

## ADDED Requirements

### Requirement: 自动更新检测
系统 MUST 能够在应用启动时检测是否有新版本可用。

#### Scenario: 启动时检查更新
- **WHEN** 用户启动桌面应用
- **THEN** 系统向更新服务器查询最新版本
- **AND** 比较当前版本与最新版本

#### Scenario: 有新版本可用
- **WHEN** 检测到新版本大于当前版本
- **THEN** 系统显示更新提示通知
- **AND** 通知包含新版本号和更新说明

#### Scenario: 无新版本
- **WHEN** 当前版本已是最新
- **THEN** 系统静默，不显示任何提示
- **AND** 应用正常启动

### Requirement: 自动下载更新
系统 MUST 能够在后台下载更新包。

#### Scenario: 同意下载更新
- **WHEN** 用户点击"立即更新"或"下载更新"
- **THEN** 系统在后台开始下载更新包
- **AND** 显示下载进度

#### Scenario: 下载完成通知
- **WHEN** 更新包下载完成
- **THEN** 系统提示用户重启应用以完成更新
- **AND** 用户可选择稍后重启

### Requirement: 静默自动更新安装
系统 MUST 能够在应用关闭后自动安装更新。

#### Scenario: 应用退出时安装
- **WHEN** 用户关闭应用且更新已下载
- **THEN** 系统自动启动安装程序
- **AND** 下次启动时运行新版本

#### Scenario: 安装失败回退
- **WHEN** 自动更新安装失败
- **THEN** 系统保留旧版本应用
- **AND** 下次启动时提示用户手动更新

### Requirement: 更新服务器配置
系统 MUST 支持配置更新服务器地址。

#### Scenario: 配置更新源
- **WHEN** 开发者设置 electron-builder 的 publish 配置
- **THEN** 系统从指定服务器获取更新信息
- **AND** 支持私有 GitHub Releases 或自建服务器

#### Scenario: 版本发布触发更新
- **WHEN** 开发者在 GitHub 发布新版本
- **THEN** 更新服务器自动包含新版本信息
- **AND** 用户应用能够检测到该版本

### Requirement: 增量更新支持
系统 SHOULD 支持增量更新以减少下载量。

#### Scenario: 增量更新可用
- **WHEN** 新版本与当前版本差异较小
- **THEN** 系统优先下载差异包
- **AND** 减少用户等待时间

#### Scenario: 增量更新不可用
- **WHEN** 无法生成增量包或版本跨度太大
- **THEN** 系统下载完整更新包
- **AND** 通知用户下载较大文件

### Requirement: 更新可跳过
用户 MUST 能够选择跳过特定版本。

#### Scenario: 跳过当前版本
- **WHEN** 用户选择"跳过此版本"
- **THEN** 系统不再提示该版本更新
- **AND** 下一个新版本时重新提示

#### Scenario: 查看已跳过的更新
- **WHEN** 用户进入设置查看更新
- **THEN** 系统显示已跳过的版本列表
- **AND** 允许用户取消跳过
